# ADR 0002：单文件交付、最小外部状态与防误操作

> 类型：架构决定 | 状态：生效 | 维护：项目维护者 | 更新：2026-11-21
> 适用：Aurora Windows 单 EXE、Linux agent 单 ELF 及后续升级和状态迁移；不代表 3.26.0 已实现

## 背景

Windows 要保留 Flutter、原生 DLL 和本机 Go agent 的现有能力；Linux 已能在 agent 二进制内携带 tmux 与 terminfo。单文件交付不能消除用户设置、身份密钥、运行状态和系统服务定义。把这些东西混在解包目录里，会让清理缓存、覆盖程序或升级失败变成数据损失。

## 决定

### 1. 只在二进制外保存必须改变或必须由系统读取的东西

| 类别 | Windows 单 EXE | Linux agent 单 ELF |
|---|---|---|
| 程序与资源 | 默认从 EXE 解包到用户私有的版本化运行目录，例如 `%LOCALAPPDATA%\Aurora3Runtime\versions\`。只放可重新提取的程序资源，不放配置、身份或会话。 | 非变动组件默认内嵌；确需解包的 tmux、terminfo 等放在可重建的运行目录，按版本或内容识别。已挂接的终端仍在使用的版本不得清理。 |
| 持久配置与状态 | 继续使用 `%LOCALAPPDATA%\Aurora3\` 作为持久入口，不因单文件交付改变现有数据位置。 | 保留实例独立的 `/etc/aurora3/agent.json` 与 `/var/lib/aurora3/`，或具名实例的对应目录。启动配置只保留监听、文件根等必要字段和机密引用。 |
| 系统接入和升级 | 无须另发安装器或辅助 EXE。稳定启动器和最小版本选择记录由程序管理；排序、签名清单等可由安装包推导的内容不另建手工维护文件。 | 稳定的 systemd 单元和一个版本切换入口由程序管理。版本目录独立于持久状态，保留当前和允许回退的上一版。 |

不为追求「磁盘上只有一个文件」而合并大附件、恢复日志或数据库；外部状态按用途控制数量、大小和保留期。项目文件仍在原目录，不因发布方式被搬迁、加密或清理。

### 2. 机密默认加密，密钥不能跟密文一起打包

- **必须纳入保护范围：** 认证令牌、API Key、OAuth 凭据、私钥；以及可能包含源码、正文或补丁的应用自有会话、附件、草稿、恢复日志和临时副本。新实现使用有完整性校验的加密，不能只加密主库、却在临时文件、日志、备份或迁移目录留下明文。
- **Windows：** 继续使用当前用户的 DPAPI 保护 Profile；新增敏感存储复用系统保护，目录仅让对应用户和受信任的系统主体访问。用户切换或换机器时不能假定原密文可解；可迁移备份必须显式导出，并独立加密。
- **Linux：** 优先使用平台提供的受保护凭据，如有可用密钥保护的 systemd 加密凭据或 TPM；也可由管理员配置外部密钥来源。持久状态的加密密钥与数据分开管理。**缺密钥、解密失败或机密存储不可用时，不静默降级为明文。** 不支持安全无人值守解锁的环境，要明确要求配置密钥来源；旧版兼容模式不能冒充已加密。
- 公共证书、公钥、版本号和 systemd 单元不需要为凑覆盖率加密；它们仍须保护完整性。程序与资源用签名和哈希确认发布来源，不用加密代替验签。**不把私钥或解密密钥写入二进制、发布包、仓库或诊断输出；不把文件藏在隐蔽位置当作安全措施。** 落盘加密保护离线副本，不能防御已经控制当前 Windows 用户或具有 Linux root 权限的攻击者。

### 3. 防误操作是升级和恢复的硬约束

1. **只重建能重建的。** 程序缓存验签、校验未通过时禁止加载；解包与清理都必须限定在已确认的程序目录，不跟随可能指向持久状态或项目的符号链接或重解析点。正常卸载保留用户状态；清除数据是独立操作，确认前列出端、实例与目录。
2. **不修成空白。** 配置或状态读取失败时显示原因并保留原件，不自动用默认值覆盖、不清空历史、不关闭加密。只有明确的新建实例且没有旧身份痕迹才能生成身份；已有部署记录或身份文件不全、损坏、证书和密钥不匹配时，停止该实例的连接初始化，要求从受保护备份恢复或由用户显式重新配对。旧版证书加载失败时可能重建，不能把该行为带入新布局。
3. **先验再换。** 配置由界面或管理入口校验后提交；保守处理管理员手动配置。写入经过独占、同卷暂存、权限检查、内容复验及原子替换；失败保留旧版本。升级只切换完整且已验签的程序版本，不顺手重写配置、权限、密钥或身份。版本号不复用。
4. **试运行不破坏回退。** 新旧程序不得并行写同一持久状态；迁移必须先验证有可用的旧状态或可逆迁移路径。若旧版无法解读新状态，不得宣称能回滚。恢复过程先查持久升级收据，不自动重放安装提交、文件写入或删除；不启动已撤回或不再被策略允许的回退版本。

## 取舍

首启要占用少量解包时间与磁盘，保留上一版也需要空间；换来离线首启、无需改造 Flutter 引擎和可回退升级。Linux 服务仍由系统管理，不因单 ELF 附带安装行为就扩大权限，也不把电源故障下的持久性或零停机当作原子切换的自然结果。

## 落地与验证

实施顺序：封装和冻结程序／状态目录边界 → 保护已有身份并区分首次初始化 → 实现按平台的密钥来源与可回退迁移 → 联调升级。保留 3.26.0 ZIP 和旧安装路径，直到迁移受验。

单二进制候选不可通过验收，除非验证：无明文机密外泄（包括暂存和备份）；删除程序缓存不会丢数据；损坏配置、缺密钥和不匹配证书均不自动重置；断线、杀进程、磁盘满和回退时不会使用混合版本或不可读的新状态；默认实例、具名实例及旧版升级数据不串写。单独记录是否验证过完整机器重启或掉电，不以模拟崩溃代替验证。
