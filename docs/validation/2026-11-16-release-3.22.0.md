## 发布过程记录

1. 新增文件进入索引后发现上游 vendored 格式和原始日志中的空白；通过 `.gitattributes` 保留证据原始字节并豁免上游空白检查，自有源码差异检查通过。
2. PowerShell transcript 未完整捕获直接输出的 Go 子进程 stdout，补用显式输出捕获重新执行 Go 验签与 Linux 版本检查；其他冒烟结果以脚本成功后生成的结构化记录为准。
3. 发布脚本对 REST 数组的计数发生一次包装错误，在草稿阶段停下。复核草稿三项资产后继续发布，没有重复上传。
4. 首次公开下载使用草稿阶段取得的地址返回 404；发布后重新读取公开 API 返回的规范地址，三项无认证下载全部通过。
