# 4.0 加密状态与文件收据源码验收

> 类型：验收记录 | 状态：已记录 | 维护：构建维护者 | 更新：2026-11-21
> 适用：`4.0.0-foundation-alpha1` 之后的未打包源码；Windows x64、WSL Ubuntu 24.04

基线 HEAD `c90db8f78a775012afefdfff72dfde8b1b6fee2e`，测试对象是包含未提交改动的工作树。Go 1.26.0、Flutter 3.47.9／Dart 3.13.7。没有重编已签名的 `4.0.0` agent，也没有迁移真机 Profile、重新打包或部署。

| 范围 | 验证结果 |
|---|---|
| 密钥与格式 | AES-GCM 记录绑定用途和标识，拒绝错密钥、内容篡改和互换。Windows 实测当前用户 DPAPI 包裹状态密钥，Linux 实测独立系统凭据目录的私有文件读取和权限拒绝。 |
| AI 存储 | 在测试进程启用加密后，检查点、增量、索引、附件、工具溢出输出以密文保存。附件原始上传分片留在有上限的内存缓冲，不写明文上传暂存。新进程能重读，错密钥或损坏记录保留。 |
| 快照 | 加密后端按文件保存认证密文，清单和对象标识不直接暴露文件名和未加钥的内容哈希；不向旧影子 Git 仓库写源码对象。验证重复捕获、Unicode 文件差异、回退计划和共享对象清理。 |
| 文件事务 | 注入实际子进程退出后重开：没有密钥时不执行回退并保留原日志，有正确密钥时恢复且重复恢复不修改文件。已提交事务检测日志损坏时也保留证据。 |
| 查询替换 | 客户端在发送前保存查询专用收据；保存失败则不发送。重开工作区并从 Profile 恢复后，证书不符不查询，目标不符不清除。查询不会重放写入或删除源；加密模式下 agent 也会加密收据。 |
| 包装器 | PowerShell 语法及参数前置检查通过，包括拒绝无效指纹、非 HTTPS 时间戳和不存在的证书。当前 Windows 证书库没有可用代码签名证书，未执行真实 Authenticode 签名。 |

Windows `go test -p 2 ./... -count=1 -timeout=8m` 和 `go vet ./...` 通过，随后单独复验修改后的替换收据。WSL 完整运行 `statecrypt`、`filetxn`、`ai`、`install`、`entry`、`wire` 包的测试，并定向复验加密 AI 存储和 `files` 收据。Flutter 全量 689 通过、20 跳过；Profile 包 60 通过（包含最终改动后的暂存路径测试，以及真实 Windows DPAPI 收据重开）；静态分析无错误和警告，GUI 合约通过。核对 3.26.0 ZIP、4.0 Alpha EXE 和 Linux ELF 的 SHA-256 均不变。

**不代表生产加密已启用。** agent 的加密存储路径只在测试中主动启用；两端生产启动仍缺可回退的受保护状态初始化、独占迁移和密钥持久化。旧影子 Git、旧明文配置、审计与备份尚未迁移，Linux 认证配置和客户端／服务端持久版本切换仍未完成。进程退出测试不能代替磁盘写满、机器重启及掉电验证。见 [正式发布门槛](../development/roadmap-4-0.md)。
