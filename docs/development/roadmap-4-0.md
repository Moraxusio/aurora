# Aurora 4.0 升级清单

> 类型：开发计划 | 状态：候选 | 维护：项目维护者 | 更新：2026-11-21
> 适用：Windows x64 客户端与本地 agent、Linux amd64 远程 agent；供 Aurora 4.0 立项

## 定位与基线

4.0 优先做可靠的本地／远程开发工作台：从打开项目、编辑与搜索、运行终端，到 AI 修改审阅和验证，发生断线或重启时能恢复，执行前能核对目标和权限。不以增加侧栏入口或推倒现有工作区模型为目标。

公开正式版仍为 3.24.0；3.x 本地基线为 [3.26.0-safety-preview1](../releases/3.26.0-safety-preview1.md)，4.0 已生成隔离的 [foundation-alpha1](../releases/4.0.0-foundation-alpha1.md)。`main` 仍位于 `c90db8f78a775012afefdfff72dfde8b1b6fee2e`，候选包含未提交改动。历史基线参见 [3.25.1 验收](../validation/2026-11-20-agent-version-3251.md) 和 [资源管理器验收](../validation/2026-11-20-explorer-preview.md)。

## P0：正式发布前必须收口

| 问题 | 证据与处置 |
|---|---|
| 排队项覆盖新 AI 权限 | **已修，覆盖排队、补充指令和待审批子代理。** 保留模型／预算快照，不恢复旧授权；返回的工具调用重新检查权限。撤回授权不是回滚已开始的操作，若有风险应停止任务并核对结果。 |
| 文件确认失去原请求的目标身份 | **已修，两个模拟连接的回归已加入。** 确认和剪贴板不迁移至新连接；删除、重命名和移动重新检查未保存文件。支持版本条件的 agent 拒绝过期源／目标；目录版本不等于整棵子树快照。 |
| 上传覆盖意图缺少服务端约束 | **已接通客户端与 agent 的版本条件。** 发起前实际查询目标，新建带 `create`，替换带 `if_match`；签名 Windows agent 已核对创建冲突，Windows/Linux 夹具覆盖过期替换。 |
| 不同 agent 构建复用同一版本号 | **已加发布身份账本与冲突回归。** 新 agent 声明 Full Access；已知支持的 3.25.1 兼容，行为不一致的旧 3.25.0 不静默降级。 |
| 粘贴替换在断线后可能遗留隐藏备份 | **3.26.0 普通文件事务替换已修。** 目标和收据同事务提交；4.0 后续源码在发送前保存查询记录，重启后可用原 agent 的 ID 和证书指纹查询，绝不重放。目录替换和旧备份处理仍未完成。 |
| AI 回退把同期其他修改当成 AI 改动 | **3.26.0 移除隐式整树回退。** 默认不恢复文件，只接受预览后明确选择的路径，版本变化时拒绝。隔离夹具验证选中 AI 文件时未选的独立保存保留。4.0 仍需改动归因、逐文件差异审阅与 orchestrator 快照覆盖，不能宣称快照差异都是 AI 写入。 |
| 远程默认执行权限过大 | **现有设计限制，不是新发现的漏洞。** Linux 默认系统服务以 root 运行；具名实例不是权限隔离。4.0 应把日常文件、终端、AI 和显式管理操作的权限分开。若短期仍保留管理员模式，迁移时明确展示现有权限，不将其宣传为工作区沙箱或多租户隔离。 |

已修问题进入 3.x 维护线，不必等 4.0 功能完成。当前范围见 [3.26.0 验收](../validation/2026-11-21-326-safety-preview.md)。续审已修复 Windows 下载发布同名竞争；还需验证远端文件名的 Windows 映射／保留名，以及目标目录重解析点。纯路径夹具证实分隔符假设不同，现有 agent 拒绝反斜杠参数，未复现通过官方 agent 越界下载。

### 4.0 单文件路线的正式发布门槛

1. **状态加密与旧版迁移。** 在写入层保护 Linux 认证与代理配置、两端的会话日志／索引、媒体及附件、快照、工具输出、文件事务和备份。新增受保护的 Linux 机密引用配置；任何阶段的候选不能把缺密钥视为可继续运行明文。未覆盖的持久数据必须阻止正式验收。旧版读取测试不等于完成加密迁移或可回退。
2. **启动确认与持久切换。** Windows 单 EXE 的完整解包不等于已有更新器；需要候选握手确认与上一版本恢复。Linux 日常更新只替换程序的路径已验证于夹具，下一步把程序版本、试启动状态和回退做成持久事务；验证机器重启、丢响应、磁盘满和不可回退状态，不修改身份。
3. **真实升级验收。** 首次安装、默认／具名实例、3.26.0 数据迁移与恢复、TLS 指纹、现有终端会话和版本撤回策略均须在隔离系统实测。任何示例中的开发密钥不得进入正式包。
4. **产物验签。** 保留 Aurora 对内嵌运行包、agent 和升级产物的发布签名，公布最终外层文件的 SHA-256。Windows 外层 Authenticode 是可选项，不是正式发布门槛；未做 Authenticode 的下载可能显示「未知发布者」，也可能被受管设备的策略拦截。

后续源码可在 [隔离启动路径](protected-state-preview.md) 启用加密状态和只读克隆：支持旧身份、配置、会话、附件、替换收据、会话引用的快照、工具输出及 Windows DPAPI 客户端状态。Linux 独立验收目录使用单一持久版本选择和试启动收据。它们未接入生产升级，不会修改既有实例；终端代理暂存、未识别的存储／审计迁移、加密后写入的回退、Windows 和 Linux 的生产启动切换仍阻断正式发布。之前的组件验收见 [状态加密与文件收据验收](../validation/2026-11-21-400-protected-state.md)。

## P1：4.0 核心功能

1. **工作区恢复。** 扩展已有文档恢复：按工作区保存 AI 未发送草稿、Git 提交草稿和任务导航；远程终端断线后恢复挂接，恢复页主动区分「可继续」「已结束」「结果未知」，不自动重放结果未知的写入、Shell 或 Git 操作。Windows 托盘恢复与退出后的本地进程持久化是两回事，后者先不承诺。
2. **文件任务操作。** 保留紧凑树、单击预览与独立右键菜单；优先加常用位置、可点击路径、传输面板的暂停／断点续传。可恢复删除先在支持的同设备范围内实现；无法恢复时明确提示。大目录、弱网、锁文件与同名冲突优先于缩略图等装饰功能。
3. **AI 改动闭环。** 把现有 Plan、建议审阅、差异、验证任务和会话回退串成一条工作流，不另外造一套编辑器。运行时显示主／子代理的实际权限、拒绝／审批原因、影响文件、预算和验证结果；连接继续负责认证与网络，Persona 负责模型参数，对话负责执行策略，保留 OpenCode 兼容标识。
4. **连接诊断与目标确认。** 首屏明确「当前是在本机还是哪台服务器、哪个根目录」，把 SSH 配对、agent 连接、模型调用、授权刷新分开检查；提供默认脱敏的诊断报告。用真实账号分别验 Chat／Responses／Anthropic 路径和支持的图片／PDF 输入；未验证的组合不写成支持。

## P2：视核心验证结果决定

- 优先为两到三套常用语言提供经实际验证的 LSP／任务／调试模板；兼容参考目前只记录 Dart LSP／DAP 实测。
- 若并行 AI 任务有实际需求，再加显式 Git 工作树隔离和分支交接。现在子代理共享同一目录，不应宣传已有隔离。
- 单文件交付可独立开展原型，遵循 [ADR 0002](../decisions/0002-single-binary-state-safety.md) 的最小外部状态、加密和防误操作门槛；既有 ZIP 和远端安装方式保留。传统安装器、macOS、Linux ARM64、跨设备同步不作为本轮前置条件。

## 阶段与发布门槛

| 阶段 | 结束条件 |
|---|---|
| 3.x 基线 | 已交付预览与源码可对应；权限与文件危险操作有回归；历史包与正式版保留。 |
| 4.0 Alpha | 确认恢复范围与权限模型，弱网／重启下不自动重复提交写入；已有连接、AI 协议和日常快捷键兼容。 |
| 4.0 Beta | 在隔离环境完成 `3.24.0 → 4.0`、`3.25.1 agent / 3.25.2 客户端 → 4.0` 的升级、失败回滚或备份恢复。检查 Profile、会话、终端、项目与草稿；在干净 Windows 和真实 Linux agent 上验收。 |
| 4.0 RC | 发布工序自动复验签名、构建产物、版本、升级策略和兼容矩阵。Windows 原生重复测 AI＋终端输出时切编辑器，按既定 60 Hz 目标检查 UI p95 ≤ 16.7 ms；补弱网／慢盘及 24 小时内存、句柄和子进程留存检测。 |

此前 Profile 测得高负载编辑器切换 UI p95 为 19.4 ms；这是旧候选不达标的记录，不是 3.25.2 的成绩。真实商业授权、长期压力和旧用户配置迁移需要分开验证，不能用 Widget 通过数替代。参见 [桌面回归](../validation/2026-11-20-desktop-workbench.md) 和 [兼容边界](../reference/compatibility.md)。
