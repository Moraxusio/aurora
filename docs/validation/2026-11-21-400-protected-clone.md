# 4.0 受保护启动与旧状态克隆验收

> 类型：验收记录 | 状态：已记录 | 维护：构建维护者 | 更新：2026-11-21
> 适用：`4.0.0-foundation-alpha1` 之后的未发布源码；Windows x64、WSL Ubuntu 24.04

基线 `c90db8f78a775012afefdfff72dfde8b1b6fee2e`，含未提交改动；Go 1.26.0。使用临时夹具、回环端口和各测试的隔离密钥。未替换生产 Profile、systemd 单元或发布包。

| 场景 | 证据 |
|---|---|
| Windows 旧版与克隆 | 校验并运行本地已签名的 3.26.0 本机 agent，由它建立配对身份。在夹具中添加旧会话、附件和收据后离线克隆，在新进程用原证书指纹进行 TLS 握手；加密会话和收据可查询，附件解密结果一致。重复启动不更改身份，并发写入、兼容模式打开加密状态、缺失密钥和不支持的旧快照均拒绝。使用旧二进制重开未改变的源验证原配对仍可用。 |
| Linux 旧版与克隆 | 校验签名的 3.26.0 Linux ELF，以它验证未动源的配对和 token。新进程用独立凭据打开受保护配置及 TLS 身份，两次回环握手通过。改写配置的公开监听字段会破坏认证；缺少凭据或凭据错误时不发布监听。隔离配置不给原项目路径，也不暴露远程升级或终端操作。 |
| 原子发布与并发 | 写入锁拒绝第二个持有者；克隆在同卷发布完整目录且不覆盖旧目标。注入失败时没有部分目标发布；若源存在新版写入锁，则不克隆正在使用的源。旧版写入者必须由操作者停止。 |
| Linux 程序替换 | 4.x 新安装器的程序替换验证升级前配置、systemd 单元和配对摘要，并用原证书指纹确认握手。发现 ID 在重启阶段变化后恢复旧程序但不自动启动它；身份原件和回退证据保留。验证范围限于安装器测试夹具，不等同于生产部署。 |

详细操作与限制见 [受保护状态隔离验收](../development/protected-state-preview.md)。没有验证把克隆期间的新写入安全回迁到旧格式，也没有验证历史快照、完整客户端 Profile、程序持久切换、systemd 重启和掉电；不得标为正式版本。当前机器没有可用的发布方 Authenticode 证书。
